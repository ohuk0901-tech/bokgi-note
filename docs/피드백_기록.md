# 복기노트 피드백 기록

이 문서는 베타 테스트 중 받은 사용자 피드백과 그에 따른 판단, 수정 내역을 누적 기록하기 위한 문서입니다.

앞으로 사용자가 대화에서 `피드백`이라고 말하며 내용을 전달하면, AI는 이 문서를 먼저 읽고 아래 규칙에 맞춰 기록하고 작업해야 합니다.

## 기록 목적

- 어떤 피드백이 있었는지 잊지 않기 위해 기록합니다.
- 단순 요청이 아니라 사용자가 실제로 어디서 막혔는지, 왜 불편했는지를 남깁니다.
- 고친 내용과 아직 남은 문제를 구분합니다.
- 나중에 디자인, 기능 개선, 우선순위 결정을 할 때 근거로 사용합니다.

## AI 작업 규칙

1. 사용자가 `피드백`이라고 말하면 먼저 피드백의 원문을 요약합니다.
2. 피드백을 아래 유형 중 하나로 분류합니다.
   - 가입/로그인
   - 홈/대시보드
   - 투자 일기 작성
   - 주간 복기
   - 다시 볼 기록
   - 대표 메모
   - 템플릿
   - 폴더/검색/휴지통
   - 모바일 사용성
   - 성능/오류
   - 보안/운영
   - 기타
3. 사용자가 겪은 실제 문제를 기능명이 아니라 행동 기준으로 다시 적습니다.
4. 바로 고칠 수 있는 문제인지, 더 판단이 필요한 문제인지 구분합니다.
5. 수정 작업을 했다면 어떤 파일을 바꿨고, 어떤 방식으로 검증했는지 기록합니다.
6. 수정하지 않았다면 왜 보류했는지와 다음에 확인할 내용을 남깁니다.
7. 기존 기록을 지우지 말고 최신 피드백을 위쪽에 추가합니다.
8. 여러 피드백이 섞여 있으면 항목을 나누어 기록합니다.

## 우선순위 기준

- `높음`: 가입, 로그인, 저장, 데이터 접근, 모바일 사용처럼 앱 사용 자체를 막는 문제
- `중간`: 핵심 흐름은 가능하지만 사용자가 헷갈리거나 반복 사용을 방해하는 문제
- `낮음`: 문구, 배치, 시각적 선호처럼 개선하면 좋지만 사용을 막지는 않는 문제

## 상태값

- `접수`: 피드백을 기록했고 아직 판단 전
- `검토 중`: 원인이나 해결 방향을 확인 중
- `수정 예정`: 해결 방향이 정해졌고 작업 전
- `수정 완료`: 코드나 문서를 수정함
- `배포 완료`: 운영 배포까지 완료함
- `보류`: 지금은 하지 않기로 결정함

## 피드백 목록

## 2026-07-15 - 메모 에디터 되돌리기 버튼과 모바일 키보드 위 툴바 필요

- 상태: 수정 완료
- 우선순위: 중간
- 유형: 투자 일기 작성 / 모바일 사용성
- 출처: 베타 사용자

### 원문 또는 요약

메모 작성 화면에 실행 취소와 다시 실행 버튼이 필요하다는 피드백이 있었다. 현재 불릿, 번호 목록, 체크박스, 내어쓰기, 들여쓰기 버튼이 메모 상단에 있는데, 노션 앱처럼 모바일 키보드 위에 툴바를 띄울 수 있는지도 검토가 필요하다.

### 사용자가 겪은 문제

사용자가 모바일에서 메모를 작성하다가 실수로 내용을 지웠거나 목록 구조를 잘못 바꿨을 때, 즉시 되돌릴 방법이 잘 보이지 않는다. 또한 목록/들여쓰기 버튼이 본문 상단에 있어 키보드를 띄운 상태에서 반복 사용하기 불편하다.

### 원인 판단

현재 TipTap 에디터 툴바는 `RichTextEditor` 상단에 고정되어 있다. 모바일 키보드가 열린 상태에서 손가락 이동 거리가 길고, 실행 취소/다시 실행 버튼은 아직 UI로 제공되지 않는다.

### 처리 방향

TipTap의 history 기능을 사용해 실행 취소/다시 실행 버튼을 추가한다. 모바일에서는 에디터가 포커스된 동안 툴바를 화면 하단, 키보드 바로 위처럼 보이는 위치에 띄우는 방식을 검토한다. 단, 웹/PWA에서는 iOS 네이티브 키보드 영역 자체에 버튼을 넣을 수 없으므로, `visualViewport`와 `position: fixed`를 이용한 하단 플로팅 툴바로 구현하는 방향이 현실적이다.

### 수정 내역

- 변경 파일: `src/components/RichTextEditor.tsx`
- 변경 내용: TipTap 실행 취소/다시 실행 버튼을 추가했고, 모바일에서는 에디터 포커스 중 하단 플로팅 툴바가 나타나도록 수정했다. 데스크톱에서는 기존 상단 툴바를 유지한다.
- 후속 변경: iPhone Safari의 키보드 보조 바가 앱 툴바를 가리는 문제가 확인되어, iOS에서 키보드가 열린 경우에만 앱 툴바를 더 위로 올리도록 보정했다.
- 후속 변경: iPhone Safari 보조 바를 줄이기 위해 제목/날짜/본문 입력 요소의 자동완성, 자동수정, 탭 이동 관련 속성을 조정했고, 모바일 툴바는 스크롤 위치 계산을 타지 않도록 화면 하단 고정 방식으로 단순화했다.
- 후속 변경: 모바일 툴바가 스크롤이나 일시적인 포커스 해제 때문에 사라졌다 다시 나타나지 않도록, 본문을 한 번 터치한 뒤에는 메모 화면에서 계속 표시되게 했다. iOS에서는 Safari 보조 바 위에 고정되도록 별도 하단 여백을 적용했다.
- 후속 변경: 모바일에서 에디터 focus 이벤트가 늦게 잡히는 경우를 줄이기 위해, 본문 영역의 터치/클릭/포커스 캡처 시점에도 툴바가 즉시 열리도록 보강했다. iOS/Android 위치 차이를 설명하는 디자인 예시 문서를 추가했다.
- 후속 변경: 고정된 bottom 값만으로는 iOS/Android 키보드 높이 차이를 안정적으로 대응하기 어려워, `visualViewport`의 실제 보이는 화면 높이와 하단 가림 영역을 기준으로 모바일 툴바 위치를 다시 계산하도록 수정했다.
- 검증 방법: `npm run lint`, `npm run build` 통과

### 남은 확인 사항

- 모바일 Safari에서 키보드 표시 상태로 툴바가 의도한 위치에 보이는지 실제 기기 확인이 필요하다. iOS Safari 보조 바가 계속 뜨는 경우 웹앱에서 강제 제거는 어려우며, 네이티브 앱 수준의 제어가 필요할 수 있다.
